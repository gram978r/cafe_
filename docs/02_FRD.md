# 프렙 카페 운영 분석 시스템 기능 요구사항 문서

## 1. 문서 범위

이 문서는 `01_PRD.md`의 기능 범위와 `design` 폴더 시안의 버튼·입력칸을 대조해 작성한다.

수업 중 구현 대상은 다음 핵심 흐름이다.

> 판매 기록 입력·수정·삭제 → 일·주·월 실적 조회 → 메뉴별 변동 수익성 확인 → 실제 손익과 재료 잔량 확인

수업 후 확장 기능은 이 문서에서 동작 방향만 정리하고, 수업 중 완료 기준에는 포함하지 않는다.

### 적용한 추천 기준

- 판매채널 선택지는 시안 기준으로 `전체`, `매장(홀)`, `포장(To-Go)`, `배달(Delivery)`을 제공한다. 원자료에 없는 채널의 기존 실적은 없을 수 있으며, 시안에서 새로 입력한 기록은 해당 채널로 저장한다.
- 주별 조회는 월요일부터 일요일까지를 한 주로 본다.
- 새 판매 기록의 식재료 원가와 포장 원가는 입력 당시 적용되는 레시피와 재료 가격 기준으로 자동 산출하고, 당시 적용값을 판매 기록에 보관한다.
- 원가나 수수료를 산출할 자료가 없으면 0원으로 처리하지 않고 계산 보류 상태로 표시한다.
- 재료 계산상 잔량은 기초 재고, 입고, 폐기·조정, 판매에 따른 레시피 사용량을 반영한다. 최신 실사수량은 계산상 잔량을 덮어쓰지 않고 별도로 비교한다.
- 실제 손익은 실제 판매와 날짜별 비용기록을 기준으로 한다. 월비용계획은 같은 비용의 월 단위 계획이므로 실제 비용과 중복해서 더하지 않는다.

### 용어

- **순매출**: 할인 등을 반영한 실제 판매 금액이다.
- **변동비**: 판매량에 따라 달라지는 식재료 원가, 포장 원가, 결제 수수료다.
- **변동 수익성**: 순매출에서 변동비를 뺀 금액이다.
- **실사**: 담당자가 재료를 실제로 세거나 측정해 확인하는 일이다.
- **집계**: 여러 기록을 기간이나 메뉴별로 모아 합산하는 일이다.
- **계산 보류**: 필요한 자료가 없어 결과를 확정하지 않는 상태다.

## 2. 전체 사용 순서

1. 사용자가 판매 기록 관리에서 판매일자, 메뉴, 판매채널, 판매수량, 단가, 할인금액을 입력한다.
2. 프로그램이 입력값을 검증하고 순매출과 당시 원가 정보를 계산해 저장한다.
3. 사용자가 저장된 기록을 수정하거나 삭제한다.
4. 사용자가 일별·주별·월별 실적 조회에서 기간을 선택한다.
5. 프로그램이 영업일, 휴무일, 마감일, 미마감일을 구분해 기간 실적을 집계한다.
6. 사용자가 메뉴별 변동 수익성에서 메뉴 분류나 메뉴명을 검색한다.
7. 프로그램이 메뉴별 순매출, 변동비, 변동 수익성을 계산하고 비교한다.
8. 사용자가 실제 손익 및 재료 잔량에서 기간을 바꾼다.
9. 프로그램이 실제 손익과 비용 상세를 표시하고, 재료별 계산상 잔량과 최신 실사수량을 비교한다.
10. 사용자가 오류나 누락을 확인하면 판매 기록을 수정하고 관련 집계가 다시 반영되는지 확인한다.

## 4. 상세 기능 요구사항

## F-01. 판매 기록 입력·수정·삭제

### 사용자가 하는 일과 입력

- `신규 판매 기록 입력` 버튼을 누른다.
- 판매일자를 입력한다.
- 메뉴를 선택한다.
- 시안에 표시된 `매장(홀)`, `포장(To-Go)`, `배달(Delivery)` 중 하나를 선택한다.
- 판매수량을 입력한다.
- 판매 단가를 확인하거나 입력한다.
- 할인금액을 입력한다. 할인이 없으면 0으로 기록할 수 있으나, 입력하지 않은 빈칸과는 구분한다.
- `판매 기록 저장` 버튼을 누른다.
- 목록의 수정 버튼을 눌러 기존 기록을 변경한다.
- 목록의 삭제 버튼을 눌러 잘못된 기록을 삭제한다.
- 날짜, 채널, 메뉴명 검색 조건으로 목록을 좁힌다.

### 프로그램이 하는 일

- 날짜, 메뉴, 채널, 수량 등 필수값을 확인한다.
- 판매수량과 단가를 이용해 총 판매금액을 계산한다.
- 할인금액을 반영해 순매출을 계산한다.
- 입력 시점의 레시피·재료가격 기준에서 식재료 원가와 포장 원가를 산출한다.
- 사용 가능한 결제 수수료 기준이 있으면 수수료를 반영하고, 없으면 계산 보류 상태로 둔다.
- 저장·수정·삭제 후 실적, 수익성, 손익 집계의 원본이 되는 기록을 갱신한다.

계산 예시:

- 판매수량 2잔
- 단가 4,500원
- 할인금액 500원
- 순매출: `2 × 4,500 - 500 = 8,500원`

### 화면과 파일에 나오는 결과

- 판매 목록에 판매일자, 메뉴, 채널, 수량, 단가, 할인금액, 순매출, 원가, 수수료가 행 단위로 표시된다.
- 목록 하단 또는 요약 영역에 선택일자의 합계가 표시된다.
- 수정·삭제 결과가 목록과 요약에 즉시 반영된다.
- 수업 중에는 화면 저장만 사용한다. 수업 후에는 시안의 `엑셀 다운로드`, `원장 인쇄`와 연결해 현재 조회 결과를 파일 또는 인쇄용 결과로 제공한다.
- 저장된 판매 기록은 F-02~F-05의 집계에 사용된다.

### 오류나 예외가 있을 때의 동작

- 필수값이 없으면 저장하지 않고 누락된 항목을 알려준다.
- 수량이 숫자가 아니거나 허용되지 않는 음수이면 저장하지 않는다.
- 단가가 음수이면 저장하지 않는다.
- 할인금액이 총 판매금액보다 크면 저장하지 않고 확인을 요구한다.
- 원가 또는 수수료 자료가 없으면 해당 기록을 저장하되, 관련 결과를 “계산 보류”로 표시한다. 없는 값을 0원으로 바꾸지 않는다.
- 마감하지 않은 미래 날짜는 확정 실적으로 표시하지 않는다.
- 같은 원자료를 엑셀과 JSON으로 중복 가져오는 기능은 수업 후 기능이며, 이번 기능에서는 파일 중복 가져오기를 처리하지 않는다.

### 직접 확인할 방법

1. 수량 2, 단가 4,500원, 할인 500원을 저장한다.
2. 목록의 순매출이 8,500원인지 확인한다.
3. 수량을 3으로 수정한다.
4. 순매출이 13,000원으로 바뀌는지 확인한다.
5. 기록을 삭제하고 목록 및 일일 합계에서 사라지는지 확인한다.
6. 새로 조회하거나 다시 열어도 저장 상태가 유지되는지 확인한다.

## F-02. 일·주·월 실적 조회

### 사용자가 하는 일과 입력

- `일별`, `주별`, `월별` 버튼 중 하나를 선택한다.
- 이전 기간 또는 다음 기간 버튼을 누른다.
- `오늘 바로가기`를 누른다.
- `전체 일자`, `마감 완료만`, `휴무·미마감` 필터를 선택한다.

### 프로그램이 하는 일

- 선택한 기간에 속하는 판매 기록만 집계한다.
- 주별 조회는 월요일 시작, 일요일 종료로 기간을 나눈다.
- 영업일, 휴무일, 마감 완료일, 미마감일을 달력 기록과 연결한다.
- 순매출, 총 판매 수량, 할인금액, 변동비를 기간별로 집계한다.
- 2026-09-19 이후의 미완성 달력 날짜는 판매 0인 확정 영업일로 취급하지 않는다.
- 기록 기간보다 앞선 날짜나 자료가 없는 날짜는 “기록 없음”으로 표시한다.

계산 예시:

- 월요일 순매출 100,000원
- 화요일 순매출 80,000원
- 두 날짜를 포함한 기간 순매출: `100,000 + 80,000 = 180,000원`

### 화면과 파일에 나오는 결과

- 기간별 총 순매출과 판매 수량이 요약 영역에 표시된다.
- 날짜별 매출 추이와 판매채널별 판매 비중이 표시된다.
- 날짜별 영업 여부, 마감 상태, 날씨, 판매 수량, 순매출, 대표 인기 메뉴, 메모가 표시된다.
- 수업 중에는 화면 조회만 제공한다.
- 시안의 `엑셀 다운로드`는 현재 조회 기간의 실적 자료를 내려받는 기능으로, `원장 인쇄`는 같은 조회 결과를 인쇄하는 기능으로 정의한다. 둘 다 수업 후 기능이다.

### 오류나 예외가 있을 때의 동작

- 선택 기간에 판매 기록이 없으면 빈 화면 대신 “기록 없음”을 표시한다.
- 휴무일은 판매량 0인 영업일과 구분한다.
- 미마감 날짜는 실적 합계에서 확정값으로 합산하지 않고 미마감 상태로 표시한다.
- 기간 일부에만 자료가 있으면 집계 대상 기간과 실제 자료 기간을 함께 표시한다.
- 메뉴나 채널 값이 원자료와 연결되지 않으면 해당 행을 누락시키지 말고 연결 오류를 표시한다.

### 직접 확인할 방법

1. 하루의 판매 기록을 저장하고 일별 조회에 반영되는지 확인한다.
2. 같은 기록이 해당 월요일 주간 조회와 해당 월간 조회에 포함되는지 확인한다.
3. 휴무일을 포함한 기간에서 휴무일이 영업 실적으로 합산되지 않는지 확인한다.
4. 2026-09-19 이후 날짜가 0원 실적으로 표시되지 않고 미마감으로 구분되는지 확인한다.

## F-03. 메뉴별 변동 수익성 조회

### 사용자가 하는 일과 입력

- 메뉴 분류 필터를 선택한다.
- 메뉴명 검색칸에 검색어를 입력한다.
- 메뉴 목록에서 메뉴를 선택한다.
- `레시피 기준 원가 보기`를 눌러 메뉴 1개 기준 원가 구성을 확인한다.

### 프로그램이 하는 일

- 선택한 기간의 메뉴별 순매출과 판매 수량을 집계한다.
- 판매 당시의 식재료 원가, 포장 원가, 결제 수수료를 변동비로 합산한다.
- 메뉴별 변동 수익성을 계산하고 순위를 표시한다.
- 임대료·인건비 등 고정비를 메뉴별로 임의 배분하지 않는다.
- 메뉴별 원가가 없거나 레시피가 연결되지 않으면 계산을 보류한다.

계산 예시:

- 순매출 8,500원
- 식재료 원가 2,000원
- 포장 원가 200원
- 결제 수수료 170원
- 변동 수익성: `8,500 - 2,000 - 200 - 170 = 6,130원`

### 화면과 파일에 나오는 결과

- 메뉴별 순매출, 판매 수량, 식재료 원가, 포장 원가, 결제 수수료, 변동 수익성이 표시된다.
- 메뉴별 순위와 원가 미입력 상태가 표시된다.
- 선택 메뉴의 레시피 재료명, 사용량, 원가 구성과 메뉴 1개당 합계가 표시된다.
- `데이터 내보내기`를 누르면 현재 조회 기간·필터·메뉴 목록 기준의 수익성 상세 자료를 리포트 파일로 내려받는다. 파일 내보내기는 수업 후 기능이다.
- 원가 미입력 메뉴의 `입력하기`를 누르면 레시피 기준 원가 상세 창을 연다. 시안에는 실제 원가 입력칸이 보이지 않으므로, 입력 항목과 저장 방식은 추가 확정 전까지 상세 편집 기능으로 확장하지 않는다.

### 오류나 예외가 있을 때의 동작

- 원가나 수수료가 빈칸이면 0원 수익으로 계산하지 않고 “원가 미입력” 또는 “계산 보류”로 표시한다.
- 레시피가 없으면 레시피 원가 상세를 열 수 없고 원인을 표시한다.
- 레시피의 적용채널과 판매채널이 맞지 않으면 해당 원가를 자동 적용하지 않는다.
- 판매 기록이 없는 메뉴는 판매량 0과 미집계 메뉴를 구분한다.
- 자료에 없는 메뉴명 검색 결과는 “일치하는 메뉴가 없음”으로 표시한다.

### 직접 확인할 방법

1. 위 예시 숫자로 메뉴 1개의 변동 수익성이 6,130원인지 확인한다.
2. 판매량을 1만큼 늘려 판매량과 변동 수익성이 함께 변하는지 확인한다.
3. 판매 기록을 수정했을 때 해당 메뉴의 순위와 합계가 바뀌는지 확인한다.
4. 원가가 빈 메뉴가 0원 수익으로 오해되지 않는지 확인한다.

## F-04. 실제 손익 조회

### 사용자가 하는 일과 입력

- 기간 변경 버튼을 눌러 일·주·월 기간을 선택한다.
- `비용 내역 펼치기`를 눌러 실제 비용 상세를 확인한다.

### 프로그램이 하는 일

- 선택 기간의 총 순매출을 집계한다.
- 식재료 원가, 포장 원가, 결제 수수료를 변동비로 집계한다.
- 선택 기간의 날짜별 비용기록을 실제 경비로 집계한다.
- 월비용계획은 실제 비용기록과 중복해서 합산하지 않는다.
- 실제 손익을 표시한다.
- 예상 손익은 수업 후 확장 기능으로 남긴다.

계산 예시:

- 순매출 8,500원
- 변동비 2,370원
- 실제 경비 3,000원
- 실제 손익: `8,500 - 2,370 - 3,000 = 3,130원`

### 화면과 파일에 나오는 결과

- 총 순매출액
- 변동비 총액
- 1차 변동 수익성
- 실제 지출 경비
- 최종 실제 손익
- 비용 항목별 상세 합계

결과는 화면에 표시하며, 이번 수업 범위에서는 손익 파일을 별도로 생성하지 않는다.

### 오류나 예외가 있을 때의 동작

- 비용기록이 없으면 비용 0원으로 확정하지 않고 “비용기록 없음”으로 표시한다.
- 비용기록이 일부 날짜에만 있으면 실제 비용 자료가 있는 기간을 표시한다.
- 월비용계획과 비용기록이 모두 존재해도 같은 비용을 두 번 더하지 않는다.
- 매출·변동비·실제 경비 중 필수 자료가 없으면 손익을 확정 결과처럼 표시하지 않는다.
- 세부 비용 합계와 최종 비용 합계가 다르면 오류 상태를 표시한다.

### 직접 확인할 방법

1. 순매출 8,500원, 변동비 2,370원, 실제 경비 3,000원을 준비한다.
2. 실제 손익이 3,130원인지 확인한다.
3. 비용 내역을 펼쳐 세부 합계가 3,000원과 일치하는지 확인한다.
4. 기간을 하루 줄였을 때 제외된 날짜의 비용이 함께 빠지는지 확인한다.
5. 월비용계획을 추가해도 실제 비용이 두 배가 되지 않는지 확인한다.

## F-05. 재료 잔량 조회

### 사용자가 하는 일과 입력

- `전체`, `차이 발생`, `정상 일치` 필터를 선택한다.
- 재료별 기초 재고, 입고, 폐기, 판매 사용량, 계산상 잔량과 최신 실사수량을 확인한다.
- 수업 중에는 기존 기록 조회만 한다.
- 시안의 `재고 실사 기록 입력`을 누르면 마감 재고 실사 입력 창을 연다. 이 입력은 수업 후 기능이다.
- 시안의 `실사 차이 일괄 원인 보고서 작성`은 차이가 발생한 재료 목록과 원인 메모를 묶어 보고서로 만드는 수업 후 기능이다.

### 프로그램이 하는 일

- 재료 11개를 재료별 단위로 독립 계산한다.
- 입고는 양수, 폐기는 음수로 반영한다.
- 실사조정은 양수와 음수를 모두 반영한다.
- 판매량과 레시피 사용량을 연결해 계산상 사용량을 산출한다.
- 계산상 잔량과 최신 실사수량의 차이를 계산한다.
- 안전재고와 비교해 상태를 표시한다.
- g, ml, 개를 하나의 총합으로 합산하지 않는다.

계산 예시:

- 기초 재고 10개
- 입고 5개
- 폐기 1개
- 판매 사용량 3개
- 계산상 잔량: `10 + 5 - 1 - 3 = 11개`
- 최신 실사수량 10개
- 실사 차이: `10 - 11 = -1개`

### 화면과 파일에 나오는 결과

- 재료명과 단위
- 기초 재고
- 기간 입고
- 기록 폐기
- 판매 사용량
- 계산상 잔량
- 최신 실사수량
- 실사 차이
- 안전재고
- 상태 판정

수업 중에는 화면 조회만 제공한다. 수업 후에는 실사 기록을 저장하고 실사 차이 보고서를 내려받을 수 있다.

### 오류나 예외가 있을 때의 동작

- 단위가 다른 재료는 서로 합산하지 않는다.
- 최신 실사수량이 없으면 “실사 없음”으로 표시한다.
- 레시피가 없거나 판매채널에 맞는 레시피가 없으면 판매 사용량을 계산 보류한다.
- 입고·폐기 기록이 없으면 실제 0과 미입력을 구분한다.
- 미마감 미래 날짜의 판매량을 확정 재고 사용량으로 반영하지 않는다.
- 계산상 잔량과 실사수량이 다르면 “실사조정 필요” 상태를 표시한다.

### 직접 확인할 방법

1. 기초 10개, 입고 5개, 폐기 1개, 판매 사용량 3개를 확인한다.
2. 계산상 잔량이 11개인지 확인한다.
3. 최신 실사수량 10개와 비교해 차이가 -1개인지 확인한다.
4. g 재료와 ml 재료가 하나의 전체 수량으로 합쳐지지 않는지 확인한다.
5. 실사수량이 없는 재료가 정상으로 오판되지 않는지 확인한다.

## F-06. 비용기록 입력·수정·삭제

### 사용자가 하는 일과 입력

날짜, 비용 항목, 금액, 비용 인식 정보를 입력·수정·삭제한다.

### 프로그램이 하는 일

비용기록을 실제 손익에 반영하고, 월비용계획과 중복 합산하지 않는다.

### 화면과 파일에 나오는 결과

비용 목록, 항목별 합계, 기간별 실제 경비가 표시된다. 이번 문서에서는 파일 출력 형식을 정하지 않는다.

### 오류나 예외가 있을 때의 동작

날짜·항목·금액이 없거나 금액이 허용되지 않는 값이면 저장하지 않는다. 중복 여부가 불명확한 기록은 저장 전 확인 상태로 둔다.

### 직접 확인할 방법

비용 하나를 추가·수정·삭제하고 같은 기간의 실제 손익이 한 번씩만 바뀌는지 확인한다.

## F-07. 엑셀 양식 내려받기·자료 가져오기

### 사용자가 하는 일과 입력

엑셀 양식을 내려받고 판매·비용·재고 기록을 양식에 맞춰 입력한 뒤 한 번에 가져온다.

### 프로그램이 하는 일

열 이름, 날짜, 단위, 필수값과 자료 유형을 검사한다. 엑셀과 JSON은 같은 기록이므로 같은 자료를 두 번 가져오지 않도록 중복을 확인한다.

### 화면과 파일에 나오는 결과

양식 파일과 가져오기 성공·실패 건수, 오류 행과 사유를 표시한다.

### 오류나 예외가 있을 때의 동작

열 이름이 다르거나 날짜·수량·단위가 잘못되면 해당 행을 가져오지 않고 오류를 보여준다. 전체 자료를 조용히 일부만 반영하지 않는다.

### 직접 확인할 방법

정상 양식, 필수값 누락 행, 단위 오류 행, 같은 자료를 두 번 가져오는 사례를 각각 확인한다.

## F-08. 재고 변동 입력·발주 참고량

### 사용자가 하는 일과 입력

재료, 일자, 입고·폐기·실사조정 유형, 수량, 단위, 사유와 공급사를 입력한다. 발주 참고 화면에서 재료별 부족 상태를 확인한다.

### 프로그램이 하는 일

입력한 재고 변동을 잔량에 반영한다. 추천 발주량은 최근 확정 판매 사용량, 납기일수, 안전재고와 구매 포장 단위를 참고해 산출하되, 실제 주문을 자동 실행하지 않는다.

### 화면과 파일에 나오는 결과

재료별 현재 잔량, 안전재고 대비 상태, 발주 참고량과 공급사가 표시된다.

### 오류나 예외가 있을 때의 동작

단위 불일치, 허용되지 않는 수량, 공급사 없는 재료는 저장 또는 추천을 보류하고 사유를 표시한다.

### 직접 확인할 방법

입고와 폐기를 각각 등록한 뒤 잔량이 반영되는지, 안전재고보다 낮은 재료가 발주 참고 목록에 나타나는지 확인한다.

## F-09. 분기·반기·연간 조회

### 사용자가 하는 일과 입력

분기·반기·연간 기간을 선택해 실적, 수익성, 손익을 조회한다.

### 프로그램이 하는 일

일·주·월 집계와 같은 원칙으로 기간을 넓혀 집계한다. 연간 자료가 전체 연도를 포함하지 않으면 부분 기간임을 표시한다.

### 화면과 파일에 나오는 결과

선택 기간의 매출, 비용, 손익, 메뉴 수익성과 재고 결과를 표시한다.

### 오류나 예외가 있을 때의 동작

자료가 없는 기간을 완전한 0 실적으로 표시하지 않는다. 부분 기간이면 “자료가 있는 기간만 포함” 상태를 표시한다.

### 직접 확인할 방법

월별 합계와 분기 합계가 일치하는지, 부분 연간 조회에 경고가 표시되는지 확인한다.

## F-10. 예상 손익 조회

### 사용자가 하는 일과 입력

예상 기간을 선택하고 예상 손익을 조회한다.

### 프로그램이 하는 일

완료된 과거 기간의 판매 흐름과 비용 계획을 기반으로 예상값을 산출한다. 예상값은 실제값과 구분하고, 계산에 사용한 기간과 기준을 표시한다.

### 화면과 파일에 나오는 결과

예상 매출, 예상 변동비, 예상 경비, 예상 손익과 실제값 비교를 표시한다.

### 오류나 예외가 있을 때의 동작

완료된 과거 자료가 부족하거나 비용 계획이 없으면 예상 결과를 확정하지 않고 “예상 불가”로 표시한다.

### 직접 확인할 방법

과거 자료가 충분한 경우 예상값이 표시되는지, 자료를 일부 제거했을 때 예상 불가 상태가 되는지 확인한다.

## F-11. 저장 데이터 백업·복원

### 사용자가 하는 일과 입력

저장 데이터를 백업하고, 백업 파일을 선택해 복원한다.

### 프로그램이 하는 일

판매, 비용, 메뉴, 레시피, 재료, 가격 이력, 영업 달력, 재고와 자료정보를 함께 보존·복원한다. 복원 전 기존 자료를 덮어쓸지 확인한다.

### 화면과 파일에 나오는 결과

백업 성공 여부, 백업 시점, 복원 대상과 복원 결과 건수를 표시한다.

### 오류나 예외가 있을 때의 동작

읽을 수 없는 파일, 일부 자료가 빠진 파일, 다른 매장의 파일은 복원을 중단하고 원인을 표시한다. 복원 실패 시 기존 자료를 부분적으로 바꾸지 않는다.

### 직접 확인할 방법

자료를 백업하고 일부 판매 기록을 수정한 뒤 복원해 원래 기록과 집계가 돌아오는지 확인한다.

## 6. 공통 데이터·기간·단위 규칙

- 기록 기간은 기본적으로 2025-07-01부터 2026-09-18까지다.
- 영업 달력의 2026-09-19부터 2026-09-30까지는 미완성 자료다.
- 금액은 원화이며 부가세 제외 금액이다.
- 재료 단위 g, ml, 개를 유지하고 서로 합산하지 않는다.
- 구매가격은 구매 용량 전체 가격이고 레시피 사용량은 메뉴 1개 기준이다.
- 빈칸과 0을 구분한다.
- 판매기록은 주문 건수가 아니라 일자·메뉴·판매채널별 집계다.
- 엑셀과 JSON은 같은 자료이므로 둘 다 가져오지 않는다.
- 월비용계획과 비용기록은 같은 비용의 다른 시간 단위이므로 중복 집계하지 않는다.

## 7. 디자인 시안 기준의 화면 동작

시안에 표시된 버튼과 입력칸은 다음처럼 처리한다. 수업 중 구현 범위와 수업 후 범위를 구분해, 시안에 보인다고 수업 중 기능으로 앞당기지 않는다.

### 판매 기록 관리 화면 (`_4`)

- 집계일자 날짜 입력칸으로 조회일을 바꾼다.
- `전체 채널`, `매장(홀)`, `포장(To-Go)`, `배달(Delivery)` 버튼으로 목록을 필터링한다.
- 메뉴명 검색칸은 메뉴명을 포함하는 기록만 남긴다.
- `신규 판매 기록 입력`은 판매일자, 메뉴 선택, 판매채널 라디오 버튼, 판매수량, 정가, 할인 총액 입력을 제공한다.
- `판매 기록 저장`은 입력을 검증한 뒤 목록에 행을 추가하거나 수정 행을 갱신한다.
- 행의 수정 버튼은 같은 입력창에 기존 값을 채운다.
- 행의 삭제 버튼은 삭제 확인 후 기록과 일일 채널 합계에서 함께 제거한다.
- 목록에는 판매일자, 메뉴명, 판매채널, 판매수량, 정가, 할인금액, 순매출액, 식재료 원가, 포장 원가, 결제 수수료, 관리 액션을 표시한다.

### 실적 조회 화면 (`_3`)

- `일별(Day)`, `주별(Week)`, `월별(Month)` 탭으로 집계 단위를 바꾼다.
- 이전·다음 기간 버튼으로 기간을 이동하고 `오늘 바로가기`로 기준일로 돌아간다.
- `전체 일자`, `마감 완료만`, `휴무/미마감` 필터로 날짜 목록을 줄인다.
- 요약 카드에는 총 순매출액, 총 판매 수량, 총 할인금액, 결제 수수료 및 원가 변동비를 표시한다.
- 일자별 매출 추이와 채널별 판매 비중을 표시한다.
- `엑셀 다운로드`는 현재 기간·필터의 실적 목록과 합계를 내려받는다.
- `원장 인쇄`는 현재 조회 결과를 인쇄용 자료로 만든다.

### 메뉴별 변동 수익성 화면 (`_1`)

- `전체`, `에스프레소`, `콜드브루`, `논커피/음료`, `베이커리` 필터로 메뉴 분류를 바꾼다.
- 메뉴명 검색칸은 해당 메뉴만 남긴다.
- 메뉴별 순위는 변동 수익성 금액과 변동 수익성 비율을 표시한다.
- `레시피 기준 원가 보기` 또는 행의 관리 버튼은 기준 판매가, 메뉴 1개당 재료 원가 구성, 포장 원가, 결제 수수료와 원가 기준일을 보여준다.
- 원가 미입력 메뉴는 `원가 미입력(0원 아님)`, `계산 보류`로 표시한다.
- `데이터 내보내기`는 현재 수익성 원장과 원가 상태를 리포트 파일로 내려받는다.
- 원가 미입력 메뉴의 `입력하기`는 원가 등록 대상의 상세 창을 연다. 시안에 입력칸이 명시되지 않은 항목은 임의로 추가하지 않는다.

### 실제 손익 및 재료 잔량 화면 (`_2`)

- `기간 변경`으로 손익과 재고를 볼 기준 기간을 바꾼다.
- `비용 내역 펼치기`는 실제 발생 비용 대분류 상세를 열고, 다시 누르면 접는다.
- `전체`, `차이 발생`, `정상 일치` 필터로 재료 목록을 줄인다.
- `재고 실사 기록 입력`은 마감 재고 실사 입력 창을 연다.
- 실사 입력 창은 재료별 기존 계산상 잔량, 단위가 붙은 실사수량 입력칸, 실사 특이사항 및 소명 메모, `취소`, `실사 수량 확정 반영` 버튼을 제공한다.
- 실사수량을 확정하면 계산상 잔량과 실사수량의 차이를 다시 표시한다. 실사수량은 입력한 단위로 저장한다.
- `실사 차이 일괄 원인 보고서 작성`은 차이가 발생한 재료와 메모를 보고서로 만든다.

### 시안의 부가 지표

시안에는 영업이익률, 목표 달성률, 전주 대비 증감률, 일평균 매출, 피크 타임, 날씨 연동 인사이트가 표시된다. 이 값들은 화면에 보이는 지표이지만 PRD에 계산 기준이 없으므로, 이번 FRD에서는 값의 계산식을 확정하지 않는다. 계산 기준이 정해지기 전에는 실제값 대신 “기준 미정” 또는 자료가 있는 항목만 표시한다.

## 8. 완료 및 검증 기준

- 판매 기록을 입력·수정·삭제할 수 있다.
- 저장한 기록이 다시 조회된다.
- 일·주·월 조회에서 기간 경계가 맞다.
- 월요일 시작 주간 조회가 일별 합계와 맞다.
- 미마감 미래 날짜가 확정된 0원 실적으로 처리되지 않는다.
- 메뉴별 변동 수익성이 순매출과 변동비 기록에 따라 바뀐다.
- 원가 미입력은 0원 수익으로 표시되지 않는다.
- 실제 손익이 선택 기간의 판매와 비용기록을 한 번씩만 반영한다.
- 재료별 단위가 유지되고 계산상 잔량과 실사수량이 구분된다.
- 폐기, 실사조정, 판매 사용량이 재료별로 구분된다.
- 입력 오류, 자료 없음, 계산 보류, 미마감 상태를 서로 구분한다.
- 대표 메뉴, 기간 경계일, 판매량 0, 빈 원가, 빈 비용, 폐기와 실사 차이를 직접 검증한다.
- 미구현 확장 기능이 구현된 것처럼 표시되지 않는다.
